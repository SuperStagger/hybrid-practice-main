# Нейросимвольний розв'язувач логічних задач

Стартовий репозиторій практичного заняття з дисципліни «Технології розробки гібридних систем штучного інтелекту».

Ваша команда будує два конвеєри для розв'язання логічних задач і порівнює їх на п'яти задачах свого набору:

- **монолітний** — мовна модель читає задачу й одразу дає відповідь;
- **гібридний** — мовна модель перекладає задачу на формальну мову обмежень (IR), розв'язувач Z3 знаходить розв'язок, а код перевіряє й оформлює результат.

Мета — не довести, що гібрид кращий, а з'ясувати, **де саме** відмовляє кожен підхід і чому.

---

## Перед заняттям

1. Налаштуйте середовище за інструкцією [`налаштування-середовища.md`](налаштування-середовища.md).
2. Переконайтеся, що `python smoke_test.py` завершується повідомленням «All checks passed».

## Структура репозиторію

| Шлях | Що це | Чи змінювати |
|------|-------|--------------|
| `problems/problems.json` | Задачі всіх команд: текст і формат відповіді | Ні |
| `problems/team-X.md` | Ті самі задачі у зручному для читання вигляді | Ні |
| `src/monolith.py` | Монолітний конвеєр — працює одразу | За бажанням |
| `src/hybrid.py` | Гібридний конвеєр — **основна робота команди** (місця `TODO(team)`) | **Так** |
| `src/ir_solver.py` | Розв'язувач IR на базі Z3 | Не потрібно |
| `src/llm.py` | Обгортка над мовною моделлю | Не потрібно |
| `src/answer.py` | Спільний формат відповіді | Ні |
| `src/run.py` | Запуск конвеєрів і збереження результатів | Не потрібно |
| `evaluate.py` | Порівняння результатів з еталоном | Ні |
| `docs/ir.md` | Опис формату IR | — |
| `results/` | Сюди зберігаються всі запуски | Створюється автоматично |

## Швидкий старт

Активуйте віртуальне середовище та запустіть монолітний конвеєр на одній задачі свого набору (замініть `A` на літеру вашої команди):

```bash
python src/run.py --team A --pipeline monolith --problem A5 --runs 1
```

Якщо з'явився рядок зі `status=...` — усе працює. Результат запуску лежить у `results/A/A5__monolith__run1.json`: там відповідь моделі, її міркування, кількість звернень до моделі та час.

Один запуск може тривати від кількох секунд до кількох хвилин — залежно від задачі та ноутбука. Щоб бачити, що модель пише просто зараз, увімкніть режим живого виводу:

```bash
# macOS / Linux
LLM_VERBOSE=1 python src/run.py --team A --pipeline monolith --problem A5 --runs 1
```

```powershell
# Windows PowerShell
$env:LLM_VERBOSE=1; python src/run.py --team A --pipeline monolith --problem A5 --runs 1
```

Відповідь моделі обмежено 2048 токенами, а очікування — 300 секундами. Якщо модель «зациклилася» чи не відповіла вчасно, запуск завершиться з помилкою `LLMError`, а не зависне; сирий вивід моделі збережеться в полі `raw_model_output`. Обидва обмеження можна змінити змінними середовища `LLM_MAX_TOKENS` та `LLM_TIMEOUT`.

## Що робить команда

Порядок роботи з гібридним конвеєром (`src/hybrid.py`):

1. **Промпт формалізатора** (`FORMALIZER_PROMPT`). Домогтися, щоб модель повертала осмислений IR хоча б для однієї простої задачі. Налагоджувати зручно так: `python src/run.py --team A --pipeline hybrid --problem A1 --runs 1`, після чого дивитися IR у полі `trace` збереженого файлу.
2. **Валідація IR** (`validate_ir`). Повертати список зрозумілих повідомлень про помилки.
3. **Одна повторна спроба.** Якщо IR невалідний, передати моделі текст помилок і попросити виправити (`solve`, позначка `TODO`).
4. **Статус розв'язку** (`run_solver`). Зараз розв'язувач зупиняється на першому знайденому розв'язку. Подумайте, чого це коштує.
5. **Прогін.** Обидва конвеєри на всіх п'яти задачах, щонайменше по два запуски:

   ```bash
   python src/run.py --team A
   ```

Розширення, якщо лишився час, — у коментарях на початку `src/monolith.py` та `src/hybrid.py`.

### Правила

- Усі команди використовують одну модель — `qwen2.5:3b`. Не змінюйте її.
- Не вписуйте в код IR, відповіді чи підказки, призначені для конкретних задач вашого набору. Промпт має бути загальним: перевірка полягає в тому, як конвеєр працює на задачах, яких він «не бачив».
- Не змінюйте `evaluate.py` та `problems/`.

## Формат відповіді

Обидва конвеєри повертають однаковий JSON:

```json
{"status": "unique | multiple | none | optimal", "solution": {"...": "..."}, "objective": null}
```

- `unique` — рівно один розв'язок; `multiple` — розв'язків кілька; `none` — розв'язку немає; `optimal` — задача оптимізації, у `objective` — найкраще значення.
- Точна структура `solution` для кожної задачі — у рядку **Answer format** (`problems/team-X.md`) та в полі `answer_format` (`problems/problems.json`).

## Оцінювання

Еталонні відповіді (`answers.json`) викладач видає на етапі оцінювання. Покладіть файл у корінь репозиторію і виконайте:

```bash
python evaluate.py --team A
```

Скрипт виведе зведену таблицю «задача × конвеєр», перелік невдалих запусків із причинами та збереже деталі кожного запуску в `results/A/evaluation.csv`.

### Класифікація помилок

Для кожного невдалого запуску визначте тип помилки — це основа вашої презентації.

| Код | Тип помилки |
|-----|-------------|
| M-R | Моноліт: хибне міркування, порушено одну з умов |
| M-S | Моноліт: хибний статус — «знайдено» розв'язок нерозв'язної задачі або не помічено неєдиності |
| H-F | Гібрид: IR валідний, але не відповідає тексту (хибна формалізація) |
| H-K | Гібрид: у формалізації бракує знання про світ, яке текст не називає явно |
| H-V | Гібрид: IR невалідний навіть після повторної спроби |
| H-I | Гібрид: хибна інтерпретація результату розв'язувача |
| H-P | Гібрид: помилка на етапі оформлення відповіді (розв'язувач мав рацію, а відповідь — ні) |

Щоб розрізнити H-F, H-K та H-P, порівняйте IR і `solver.first_solution` з поля `trace` у файлі запуску з текстом задачі.

## Формат здачі

1. Файл `results/<команда>/evaluation.csv`.
2. Три слайди у форматі PDF (4 хвилини доповіді):
   - таблиця результатів 5 задач × 2 конвеєри з кодами помилок;
   - найпоказовіша відмова моноліту та найпоказовіша відмова гібрида — з фрагментом відповіді або IR;
   - висновок: для яких задач доцільний кожен підхід і яка одна зміна найбільше покращила гібрид.

## Якщо щось не працює

| Симптом | Що робити |
|---------|-----------|
| `Ollama is not reachable` | Запустіть застосунок Ollama або `ollama serve` |
| `LLMError: model output does not match the schema` | Модель повернула невалідний JSON. У файлі запуску є поле `raw_model_output` — подивіться, що саме вона видала |
| `HybridError: invalid IR` / `solver rejected the IR` | Помилка формалізації або валідації — див. `trace` у файлі запуску |
| Запуск дуже повільний або здається, що завис | Увімкніть `LLM_VERBOSE=1`, щоб бачити вивід моделі. В іншому терміналі `ollama ps` покаже, чи модель працює на CPU чи GPU. Працюйте на найшвидшому ноутбуці команди; `--runs 1` під час налагодження |
| `LLMError: the model hit the 2048-token limit` | Модель писала надто довго або зациклилася. Подивіться `raw_model_output`; спробуйте вимагати в промпті коротших міркувань |
| `LLMError: no answer from the model within 300 s` | Ноутбук надто повільний для цієї задачі: інший ноутбук команди або `LLM_TIMEOUT=600` |
