# Проміжне представлення (IR)

IR — це JSON-опис задачі у вигляді цілочисельних змінних та обмежень. Його створює LLM-формалізатор, перевіряє ваш код валідації, а розв'язує `src/ir_solver.py` за допомогою Z3. IR — це контракт на шві між імовірнісним компонентом (моделлю) та детермінованим (розв'язувачем).

## Структура

```json
{
  "variables":     {"<ім'я>": [lo, hi]  або  {"values": [v1, v2, ...]}},
  "all_different": [["<ім'я>", "<ім'я>", ...], ...],
  "constraints":   ["<вираз>", ...],
  "objective":     {"maximize": "<вираз>"}  або  {"minimize": "<вираз>"}
}
```

| Поле | Обов'язкове | Значення |
|------|-------------|----------|
| `variables` | так | Цілочисельні змінні. `[lo, hi]` — діапазон включно; `{"values": [...]}` — явний перелік допустимих значень |
| `all_different` | ні | Групи змінних, значення яких мають бути попарно різними |
| `constraints` | ні | Вирази, кожен з яких має бути істинним |
| `objective` | ні | Лише для задач оптимізації: що максимізувати або мінімізувати |

Імена змінних — ідентифікатори: латинські літери, цифри та підкреслення, без пробілів і не з цифри на початку.

## Мова виразів

| Дозволено | Приклад |
|-----------|---------|
| Цілі числа, імена змінних | `3`, `Red`, `slot_2` |
| Арифметика `+ - * // %` | `A + B == 10`, `X % 2 == 0`, `T // 60 == 9` |
| Порівняння `== != < <= > >=` | `A < B`, `1 <= X <= 3` |
| Логіка `and or not` | `(A == 1) or (B == 1)`, `not (A == B)` |
| Модуль `abs()` | `abs(A - B) == 2` |
| Дужки | `(A + B) * 2 == C` |

Будь-яка інша конструкція (виклики інших функцій, рядки, дійсні числа, списки у виразах) відхиляється з повідомленням `ValueError`.

**Порівняння як число.** Усередині арифметики порівняння дорівнює 1, якщо воно істинне, і 0, якщо хибне. Це дозволяє рахувати:

```text
(A == 1) + (B == 1) + (C == 1) == 1        рівно одна зі змінних дорівнює 1
X == (Y > Z)                               X дорівнює 1 тоді й лише тоді, коли Y > Z
```

## Приклад

> Three trains leave from platforms 1, 2 and 3: an intercity, a regional and an express, one per platform. The express does not leave from platform 1. The regional leaves from a platform with a lower number than the intercity. The intercity does not leave from platform 3.

```json
{
  "variables": {"Intercity": [1, 3], "Regional": [1, 3], "Express": [1, 3]},
  "all_different": [["Intercity", "Regional", "Express"]],
  "constraints": ["Express != 1", "Regional < Intercity", "Intercity != 3"]
}
```

Розв'язок: Regional = 1, Intercity = 2, Express = 3.

## Приклад із явним доменом та оптимізацією

Змінні зі значеннями лише з переліку:

```json
{"variables": {"Year": {"values": [1998, 2003, 2011]}}}
```

Вибір предметів у межах бюджету: кожна змінна 0 або 1 означає «не брати / брати».

```json
{
  "variables": {"Tent": [0, 1], "Stove": [0, 1], "Camera": [0, 1]},
  "constraints": ["4*Tent + 3*Stove + 5*Camera <= 8"],
  "objective": {"maximize": "7*Tent + 4*Stove + 6*Camera"}
}
```

## Виклик розв'язувача

```python
from ir_solver import solve
result = solve(ir, limit=N)
```

`limit` — найбільша кількість розв'язків, які шукає розв'язувач. Результат:

| Поле | Зміст |
|------|-------|
| `status` | `"unique"`, `"multiple"`, `"none"` або `"optimal"` |
| `solutions` | Список знайдених розв'язків (словник «змінна → значення»), не більше `limit` |
| `objective` | Лише для оптимізації: найкраще значення цільової функції |

Для задач з `objective` розв'язувач повертає `status = "optimal"`, значення `objective` та оптимальні розв'язки.

Функція `build(ir)` з того самого модуля лише будує модель без розв'язування та піднімає `ValueError` з читабельним повідомленням для невідомих змінних і недозволеного синтаксису — зручно для валідації.
